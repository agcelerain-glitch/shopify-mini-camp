## Shopify Flow とは・利用できるプランと基本概念

**Shopify Flow** は Shopify 管理画面上でコードを書かずにビジネス自動化ワークフローを構築できるノーコードツールです。

<mark>利用できるのは **Advanced プランおよび Shopify Plus** のみです。Basic・Grow プランでは使用できません。</mark>

**Flow の3つの基本構成要素：**

| 要素 | 役割 | 例 |
|---|---|---|
| **トリガー** | 自動化を開始するきっかけとなるイベント | 「注文が作成された」「在庫数が指定値以下になった」「顧客が作成された」（30種類以上） |
| **条件** | トリガー発生時に「どの場合に実行するか」を絞り込むフィルター | 「注文金額が5万円以上」「顧客タグに『member』が含まれる」（AND / OR で組み合わせ可） |
| **アクション** | 条件を満たした場合に実行する処理 | 「顧客にタグを追加」「注文をアーカイブ」「Slack にメッセージを送る」「HTTP リクエスト送信」 |

<u>Flow は一度設定すれば 24時間365日自動で動作し、手作業での繰り返し業務を排除することで運用コストを大幅に削減できます。</u>

> 💡 **Flow の画面を確認してみよう:** Advanced プランをお使いの場合、管理画面「**Flow（アプリ）**」を開き、テンプレートライブラリから「在庫が少ない商品のメール通知」などの既成テンプレートを確認してみましょう。トリガー→条件→アクションの流れが視覚的に確認できます。

## 実用的なフローの構築例

**フロー例1：在庫アラートフロー**

最も基本的なユースケースです。

1. **トリガー**：「在庫数が変更された」
2. **条件**：「在庫数が5以下」
3. **アクション**：「担当者にメール送信」または「Slack チャンネルに通知」

売り切れ間際の商品を自動検知できます。

**フロー例2：不正注文フラグフロー**

<mark>不正リスクの高い注文を自動でホールドし、担当者が見落とすリスクを大幅に減らします。</mark>

1. **トリガー**：「注文が作成された」
2. **条件**：「Shopify の不正リスクスコアが High」**かつ**「注文金額が3万円以上」
3. **アクション**：担当者に確認メールを送信 ＋ 注文に「要確認」タグを付与

**フロー例3：ロイヤルティタグ自動付与フロー**

顧客の累計購入額に応じてランクタグを自動管理します。

1. **トリガー**：「注文が支払い済みになった」
2. **条件**：「顧客の累計購入金額が5万円を超えた」
3. **アクション**：「silver-member」タグを追加 ＋「standard」タグを削除

<u>ランクに応じてメールマーケティングツール（Klaviyo など）がセグメントを自動更新し、専用オファーを配信する連携が実現できます。</u>

> 💡 **在庫アラートフローを作ってみよう:** Flow テンプレートライブラリから「在庫が少ない商品のメール通知」を選択し、在庫数の閾値と通知先メールアドレスを自分の環境に合わせて設定しましょう。設定後は実際に商品の在庫を閾値以下に変更してテストしてください。

## フローのテストとトラブルシューティング

<mark>Flow では本番環境に影響を与えずにテストを行うことが重要です。フローの画面右上にある「**テスト**」ボタンを使うと、実際のトリガーを発生させずにサンプルデータでアクションが正しく動作するか確認できます。ただし**メール送信・外部 API 呼び出しなどは実際に実行されるため**、テスト時はテスト用のアドレスや Webhook.site などのテスト用 URL を使うようにしてください。</mark>

**実行履歴の確認：**

フローを有効化した後は「**実行履歴**」タブから過去のログを確認できます。エラーは赤いバッジで表示され、何のアクションがなぜ失敗したかの詳細が記録されています。

**よくある失敗原因：**

- 参照している顧客タグの表記ゆれ（半角・全角・大文字小文字）
- 外部 Webhook の URL が変更された
- HTTP アクションで認証ヘッダーが正しく設定されていない

<u>複数のフローが同じトリガーで発火する場合は実行順序が保証されないため、互いに干渉しないよう設計し、本番運用前には必ずテスト注文を使って End-to-End での動作を確認してから有効化してください。</u>

> 💡 **実行履歴でフローの動作を確認してみよう:** 既存または作成したフローの「実行履歴」タブを開き、「成功・スキップ・失敗」のいずれかが記録されていることを確認しましょう。「スキップ」は条件に一致しなかった（正常）で、「失敗」だけが問題です。失敗の詳細をクリックして原因を読む練習をしてください。
