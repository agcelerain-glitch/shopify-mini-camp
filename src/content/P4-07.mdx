## ページ速度が EC 売上に直結する理由

<mark>Google の調査（2023年）では「**モバイルページの読み込みが1秒遅くなるたびにコンバージョン率は約 20% 低下する**」というデータが示されています。EC サイトにおいてページ速度は単なる技術的な問題ではなく、直接売上に影響するビジネス指標です。</mark>また Google は **Core Web Vitals（CWV）** を検索順位の評価要素に採用しており、ページ速度が低いサイトは SEO 的にも不利になります。CWV の3指標は「**LCP（Largest Contentful Paint）**」（最も大きなコンテンツの表示完了時間・2.5秒以下が目標）、「**INP（Interaction to Next Paint）**」（ユーザー操作への応答速度・200ms 以下が目標）、「**CLS（Cumulative Layout Shift）**」（レイアウトのズレの度合い・0.1以下が目標）です。Shopify ストアの速度測定は **Google PageSpeed Insights**（無料・URL を入力するだけ）と **GTmetrix**（詳細なウォーターフォール分析）で行います。<u>Shopify 管理画面の「オンラインストア → テーマ → ...（ドット3つ）→ スピードレポート」でも簡易的なスコアが確認でき、同業他社との比較スコアも表示されます。まず現状のスコアを計測してから改善を始めることが重要です。</u>

> 💡 **PageSpeed Insights でスコアを確認してみよう:** Google 検索で「PageSpeed Insights」を開き、自分のストアの URL を入力してモバイルスコアを確認しましょう。「診断」セクションに表示される改善提案のうち、上位3つを確認してください。

## Shopify テーマの速度改善：画像・アプリ・JavaScript

<mark>**画像の最適化**は最も効果が大きく、かつすぐに実施できる改善です。商品画像は **2048px × 2048px 以内・ファイルサイズ 1MB 以下**を目安とし、バナー画像は横幅 1440px で圧縮率を上げた WebP 形式が理想です。</mark>Shopify は画像を自動的に CDN 経由で配信し WebP 形式への自動変換も行いますが、アップロード前の元画像のサイズが大きすぎると効果が薄れます。Liquid テンプレートでは `<img>` タグに `loading="lazy"` と `width`・`height` 属性を設定することで、スクロール前の画像の先読みを防ぎ、CLS を防止できます。**アプリの精査**も重要です。インストールしたまま使っていないアプリは削除してください。Shopify アプリはアンインストール後もテーマファイルに JavaScript やスタイルシートのコードを残すことがあり、不要なスクリプトがページ読み込みを遅らせます。<u>ブラウザの開発者ツールの「ネットワーク」タブで読み込まれているスクリプト一覧を確認し、不要なものを `theme.liquid` から手動で削除することが必要な場合があります。</u>テーマ内の `<script>` タグに `defer` または `async` 属性を付けることで、JavaScript の読み込みが HTML のパースをブロックしなくなります。

## Core Web Vitals の改善と継続モニタリング

**LCP（最大コンテンツの表示）** を改善するには「ファーストビューに表示される最も大きい要素（多くの場合はヒーロー画像またはテキスト）」の表示を優先させることが重要です。<mark>ヒーロー画像は `loading="lazy"` を付けず、逆に `fetchpriority="high"` 属性を付けて優先読み込みさせます。フォントについては `font-display: swap` を CSS に設定して、カスタムフォントの読み込み中もシステムフォントで表示される状態にしておくことで、**フォント起因の表示遅延を防ぎます。**</mark>**CLS（レイアウトズレ）** は「画像に width / height 属性が指定されていない」「Web フォントの読み込み完了で文字幅が変わる」「広告や動的コンテンツが後から挿入される」のいずれかが原因であることがほとんどです。テーマ内のすべての `<img>` タグに明示的なサイズを指定することで大部分の CLS は解消できます。<u>改善後は Google Search Console の「ウェブに関する主な指標」レポートで実際のユーザーデータ（フィールドデータ）を定期的に確認します。PageSpeed Insights のスコアは「ラボデータ」であり実際のユーザー環境と異なることがあるため、Search Console のフィールドデータで本番環境での CWV を継続的にモニタリングし、改善施策の前後で比較することが最終的な評価として適切です。</u>
