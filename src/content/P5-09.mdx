## テーマ開発における品質管理の重要性

EC サイトは一度デプロイに失敗すると売上に直接影響します。**CI/CD（継続的インテグレーション / 継続的デリバリー）** はコードの変更を自動でテスト・デプロイするパイプラインです。

<mark>Shopify テーマ開発における品質チェックの第一歩は **Theme Check**（公式 Liquid 静的解析ツール）です。`theme check` コマンドひとつで、未定義変数の参照・非推奨フィルターの使用・パフォーマンス上の問題・アクセシビリティの警告などを自動検出できます。</mark>

**Theme Check が検出できる代表的な問題：**

| 問題 | 重要度 |
|---|---|
| 存在しない Liquid フィルターの使用（typo 等） | ERROR |
| `{% render %}` で存在しない変数を渡している | ERROR |
| `{% include %}` の使用（非推奨。`{% render %}` に移行推奨） | WARNING |
| 画像要素に `width` / `height` 属性がない | WARNING |
| `<a>` タグに `href` がない | WARNING |

**セットアップ：**

- `.theme-check.yml` をプロジェクトルートに置くと特定ルールの無効化・重要度の調整が可能
- VS Code 拡張「Shopify Liquid」をインストールするとエディタ上でリアルタイムに結果が表示される

<u>チームの方針として「ERROR は絶対に通さない、WARNING はコメントで理由を書けば許容する」といったルールを決めておくと、コードレビューでの議論が減ります。</u>

> 💡 **Theme Check をローカルで実行してみよう:** Shopify CLI がインストール済みなら `shopify theme check` を実行してみましょう（または `gem install theme-check` でインストール）。ERROR と WARNING の件数を確認し、ERROR から優先的に修正してください。`theme-check --list` で全ルールの一覧と説明が確認できます。

## GitHub Actions でのワークフロー設計

**ブランチ戦略（Shopify テーマ開発の定番）：**

```
feature/* → develop（プレビュー確認）→ main（本番デプロイ）
```

PR 作成時に Theme Check・ビルド確認が自動実行され、`main` へのマージ時に本番ストアへの自動デプロイが走るパイプラインを構築します。

```yaml
# .github/workflows/theme-check.yml
name: Theme Quality Check
on:
  pull_request:
    branches: [develop, main]

jobs:
  theme-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with: { ruby-version: '3.2' }
      - run: gem install theme-check
      - run: theme-check --fail-level error
```

```yaml
# .github/workflows/deploy.yml
name: Deploy to Production
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: npm install -g @shopify/cli
      - name: Deploy theme to production
        env:
          SHOPIFY_CLI_PARTNERS_TOKEN: ${{ secrets.SHOPIFY_PARTNERS_TOKEN }}
        run: |
          shopify theme push \
            --store=${{ secrets.SHOPIFY_STORE_DOMAIN }} \
            --theme=${{ secrets.SHOPIFY_THEME_ID }} \
            --nodelete
```

<mark>`--nodelete` フラグはリモートにあってローカルにないファイルを削除しない安全オプションです。本番デプロイ前には必ずステージング（develop ブランチ）でのプレビュー確認を行うルールを設けましょう。</mark>

<u>`secrets` に `SHOPIFY_PARTNERS_TOKEN`・`SHOPIFY_STORE_DOMAIN`・`SHOPIFY_THEME_ID` を登録しておきます。`shopify theme list` コマンドでストアの全テーマ ID を確認できます。</u>

> 💡 **CI パイプラインを設定してみよう:** 上記の `theme-check.yml` を `.github/workflows/` に保存し、PR を作成して Theme Check が自動実行されることを確認しましょう。ERROR があれば PR がマージできない状態になることで、品質ゲートが機能していることを確認できます。

## E2E テストと視覚的回帰テスト

**Playwright** は Microsoft が開発したブラウザ自動化ライブラリで、Chrome・Firefox・Safari に対応した E2E テストを記述できます。

<mark>EC サイトのゴールデンパス（「商品詳細 → カートに追加 → チェックアウト開始」の一連フロー）を自動テストしておくと、テーマのコード変更でカートが壊れるような重大なデグレードを即座に検出できます。</mark>

```typescript
// e2e/cart.spec.ts
import { test, expect } from "@playwright/test";

test("商品をカートに追加できる", async ({ page }) => {
  await page.goto("/products/test-product");
  await page.selectOption('select[name="id"]', { index: 0 });
  await page.click('[data-testid="add-to-cart"]');
  await expect(page.locator('[data-testid="cart-count"]')).not.toHaveText("0");
});

test("チェックアウトページに進める", async ({ page }) => {
  await page.goto("/cart");
  await page.click('[data-testid="checkout-button"]');
  await expect(page).toHaveURL(/checkout\.shopify\.com|\/checkouts\//);
});
```

Shopify のテスト用クレジットカード番号（`4242 4242 4242 4242`、有効期限は未来の任意の日付、CVV は任意の3桁）をテストデータとして使えます。

**視覚的回帰テスト：**

**Chromatic** や **Percy** は PR ごとにスクリーンショットを比較してデザインの意図しない変化を検出します。テーマのすべてのページタイプ（トップ・商品詳細・コレクション・カート・404）のスクリーンショットを管理することで、CSS 変更による予期しないレイアウト崩れを自動で見つけられます。

<u>E2E テストの追加順序は「①ゴールデンパス（購入フロー）→ ②重要な商品ページ → ③エッジケース（在庫切れ・コレクション空など）」の優先度で進めると、投資対効果が最大になります。</u>

> 💡 **Playwright を導入してみよう:** `npm init playwright@latest` で Playwright をセットアップし、`e2e/cart.spec.ts` に上記のテストコードを追加しましょう。`npx playwright test` を実行して、カートに商品を追加するフローが自動でテストされることを確認してください。失敗した場合はスクリーンショットが自動保存されるため、原因の特定が容易です。

## よくある質問

**Q. 複数の環境（開発・ステージング・本番）のテーマ ID はどう管理すればよいですか？**

GitHub Environments を使って環境ごとに `SHOPIFY_THEME_ID` を分けて管理するのがベストプラクティスです。`development` 環境には開発テーマ ID を、`production` 環境には公開テーマ ID を登録します。<u>開発テーマはマーチャントには見えないため、本番ストアの一般公開に影響を与えずに安全に作業できます。`shopify theme list` で全テーマの ID と状態を確認できます。</u>
