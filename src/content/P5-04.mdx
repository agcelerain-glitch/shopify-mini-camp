## Shopify API エコシステムの全体像

Shopify はストアのデータにアクセスするための API を複数提供しています。

**主要な API の比較：**

| API | 用途 | 認証方式 | プロトコル |
|---|---|---|---|
| **Admin API** | ストア管理者権限でのフルアクセス | プライベートアクセストークン / OAuth | REST + **GraphQL**（推奨） |
| **Storefront API** | 購入者向けの公開データ取得 | Storefront Access Token（公開鍵） | **GraphQL のみ** |
| **Customer Account API** | 顧客アカウント情報へのアクセス | — | GraphQL |

<mark>Admin API は REST と GraphQL の両方が使えますが、**Shopify は GraphQL への一本化を推進**しており、新機能は GraphQL のみで提供されるケースが増えています。**Storefront API は GraphQL のみ**です。</mark>

**GraphQL が REST より優れる3つのポイント：**

1. 必要なフィールドだけリクエストできる（過不足のないデータ取得）
2. 1回のリクエストで複数リソースを取得できる
3. 型システムによるスキーマ定義（IDE の補完が効く）

<u>Shopify Admin の `https://YOUR_STORE.myshopify.com/admin/apps/graphiql` にアクセスすると GraphiQL（グラフィカルな GraphQL エクスプローラー）が使えるため、クエリの試作・動作確認が対話的に行えます。</u>

> 💡 **GraphiQL で商品を取得してみよう:** ブラウザで `https://YOUR_STORE.myshopify.com/admin/apps/graphiql` を開き（YOUR_STORE はあなたの myshopify.com ドメイン）、`{ products(first: 3) { edges { node { id title } } } }` を入力して実行してみましょう。商品データが JSON で返ってくることを確認してください。

## GraphQL の基本：クエリとミューテーション

GraphQL の操作は `query`（読み取り）と `mutation`（書き込み）の2種類です。

<mark>Shopify の GraphQL は **Relay 仕様**に準拠しているため、`edges` と `node` という構造になっています。ページネーションは `after: $cursor` と `pageInfo.hasNextPage` / `endCursor` の組み合わせで実装します。</mark>

**商品10件を取得するクエリ（Admin API）：**

```graphql
query GetProducts($cursor: String) {
  products(first: 10, after: $cursor) {
    edges {
      node {
        id
        title
        handle
        status
        priceRangeV2 {
          minVariantPrice { amount currencyCode }
        }
        totalInventory
      }
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

**在庫数を更新するミューテーション：**

```graphql
mutation InventoryUpdate($id: ID!, $available: Int!) {
  inventoryAdjustQuantity(
    input: { inventoryItemId: $id, availableDelta: $available }
  ) {
    inventoryLevel { available }
    userErrors { field message }
  }
}
```

<u>`userErrors` は Shopify GraphQL の慣習で、ミューテーション失敗時にエラー内容が返る配列です。HTTP ステータスコードが 200 でも `userErrors` が空でない場合は論理的な失敗なので、必ずチェックしてください。</u>

> 💡 **GraphQL クエリを試してみよう:** GraphiQL を開き、上記の `GetProducts` クエリを貼り付けて実行してみましょう。次に `first: 10` の数を変えたり、`totalInventory` フィールドを削除したりして、返ってくるデータがどう変わるかを確認してください。

## Admin API vs Storefront API の実践的な使い分け

<mark>**Admin API はサーバーサイドでのみ使うべきです。**アクセストークンが漏洩するとストアの全データに無制限アクセスされる危険があるため、`.env` ファイルに保存してフロントエンドに渡してはいけません。</mark>

**使い分けの原則：**

| シナリオ | 使うべき API |
|---|---|
| 注文処理・在庫更新・顧客管理（バックエンド） | Admin API |
| 外部システム（ERP・WMS）との同期 | Admin API |
| 商品一覧・詳細の表示（フロントエンド） | Storefront API |
| カートの作成・商品追加・チェックアウト生成 | Storefront API |
| コレクション・タグ検索 | Storefront API |

<u>**カスタムアプリやバックエンド処理には Admin API、ユーザー向けのショッピング体験を作るには Storefront API** と覚えておけば迷いません。Storefront Access Token は公開鍵のため、コードに埋め込んでも安全です（公開された情報しか取得できない）。</u>

**API レート制限への対応：**

Shopify のレート制限は「コストベース」を採用しており、クエリの複雑さに応じてコストが加算されます。`X-Shopify-Shop-Api-Call-Limit` レスポンスヘッダーを監視し、制限に引っかかった場合はリトライロジック（指数バックオフ）を実装するのが定石です。

> 💡 **環境変数の管理を確認してみよう:** 手元のプロジェクトに `.env` ファイルがある場合、`SHOPIFY_ADMIN_API_TOKEN` のような Admin API トークンが `NEXT_PUBLIC_` プレフィックスを付けずに定義されているか確認しましょう。`NEXT_PUBLIC_` が付いているとブラウザに公開されてしまいます。

## よくある質問

**Q. Admin API と Storefront API を同じアプリで両方使うことはできますか？**

はい、できます。よくあるパターンは「バックエンドが Admin API で注文・在庫を管理し、フロントエンドが Storefront API でカート操作や商品表示を行う」という構成です。<u>この場合 Admin API のトークンはバックエンドのみに置き、フロントエンドには一切渡しません。Storefront Access Token だけをフロントエンドに渡します。</u>

**Q. Webhook と API の違いは何ですか？いつ使い分けますか？**

API はこちらからリクエストを送って情報を取得・変更するプル型、Webhook は Shopify からイベント発生時に指定 URL へデータが送られてくるプッシュ型です。「注文が入ったら即座に外部システムに通知したい」などリアルタイム連携には Webhook が、「在庫チェックを定期的にしたい」など任意のタイミングでの操作には API が適しています。
